# Ayugramf の macOS 向け変更

GitHub のフォーク: https://github.com/kimmi0815/Ayugramf

ベースは AyuGramDesktop `v7.0.9`
(`032ad328549cff9f612d106d8660fbc03eb43130`)。
このMacに入っているAyuGramのバージョンに合わせている。
作業ブランチは `codex/macos-customization`。

## 複数チャットのエクスポート

各チャット／チャンネルのメニューからエクスポートを開始すると、それぞれ
独立した設定・進捗ウィンドウを開く。同じアカウント・チャット・トピックを
もう一度指定した場合は既存のウィンドウを開く。

キャンセルはその書き出しだけに作用する。ログアウト時は対象アカウントの
書き出しを確認し、アプリ終了時は全アカウントの書き出しを順に確認する。
チャット上部の進捗表示は実行中の書き出しを選び、設定を開いただけの
別チャットに切り替わらない。

保存先の下に `ChatExport_日付` などの専用フォルダを原子的に確保する。
同名があれば番号を付け、確保に失敗した場合は書き込みエラーとして止める。

同じアカウントの書き出しは、一つのTakeoutセッションを共有する。
既に許可されたデータの種類とファイル容量の範囲内なら同時に進める。
別の種類のデータや、より大きなファイル容量を要求する書き出しは、
先の処理が終わるまで「初期化中」で待機する。
セッションを終了するのは、共有している最後の書き出しが終わったときだけ。
APIの待機時間や取得制限は既存のエラー表示を使う。
開始要求の一時エラーも終了扱いにし、必要ならユーザーが再実行する。
終了したアカウントの古い開始要求が後から自動再試行されるのを防ぐため。

2026-10-06の実アカウントでの確認では、旧実装が二つ目の
Takeoutセッションを作り、先の処理が `TAKEOUT_INVALID` で止まった。
セッション共有の修正後に、実データの複数同時取得を確認する必要がある。

## 言語を指定した自動翻訳

AyuGram設定の「メッセージを翻訳」に、自動翻訳の切り替え、翻訳元言語の
複数選択、翻訳先言語の選択を追加する。初期値はオフ、ロシア語から日本語。
画面に表示される受信メッセージを既存の選択済み翻訳プロバイダーで訳す。

通常のチャット翻訳を優先する。翻訳を無効にしたチャット、送信メッセージ、
翻訳先と同じ言語のメッセージは自動翻訳しない。
設定は既存の `ayu_settings.json` に保存する。
リッチメッセージは既存の実装に従ってTelegram APIを使う場合があり、
GoogleやYandexを選んだ場合もこの経路は共通となる。

## Premiumへの案内

設定、購読・ギフト購入、各機能の案内、対応する内部リンクを共通の
`Settings::PremiumPromotionAllowed()` で抑制する。
契約状態とサーバー上の機能制限は既存の判定を使う。
Stars、受け取ったギフト、通常のプライバシー操作は維持する。

## 日本語UI

言語一覧に「日本語」を追加し、Telegramの
[`ja-beta` クラウド言語パック](https://t.me/setlanguage/ja-beta) を使う。
旧 `ja` の設定は読み込み時に移行する。
サーバーが返す `ja-raw` は日本語パックの別名として受け取り、選択と保存には
`ja-beta` を使う。別言語へ切り替えた後の古い日本語応答は取り込まない。
主要な設定・ログイン・メニューの日本語と、AyuGram独自の411キー、
追加した自動翻訳の4項目を同梱する。残りの翻訳はクラウドから取得する。
出典と更新方法は [日本語の翻訳資料](../Telegram/Resources/langs/ja_ayu.md) に記載。

## 検証とビルド

並列エクスポートの管理処理は、実際の `export_manager.cpp` とRPLを使った
独立テストで確認する。

```sh
bash tests/parallel_export/run.sh
bash tests/parallel_export/run_output.sh
bash tests/parallel_export/run_takeout_session.sh
bash tests/parallel_export/run_takeout.sh
python3 tests/japanese_ui/verify.py
python3 tests/automatic_translation/run_tests.py --native-recognition
```

このテストはQt UI、バックグラウンドキュー、Telegram通信を代替している。
アプリ全体のビルド・起動・実アカウントでの確認の代わりにはならない。
管理処理9項目、保存先処理5項目、日本語1,237キー
（本体822、AyuGram415）の検査は通過した。
Takeout修正では、API経路9項目とセッション共有・終了処理20項目も通過した。
エクスポート関係の計43項目はASanとUBSanを使い、現行ソースの処理を実行する。
通信とQtの寿命管理はテスト用の型で代替する。対象と制限の詳細は
[回帰テストの説明](../tests/parallel_export/README.md) に記載。
日本語の切り替え処理も現行ソースを抽出して実行し、同梱値の適用後に
画面更新を一度通知すること、英語への復帰、旧 `ja` の移行を確認した。
保存形式と通信順序はソース上の契約を検査しており、Qtでの読み書きや
通信コールバックはこの独立テストの対象に含まない。
自動翻訳は、設定・表示対象・キャッシュ表示・編集後の応答・バッチ分離の
56条件を確認し、macOS標準の言語判定6例も通過した。
保存先と日本語の解析テストは現行ソースの該当処理をそのまま抽出して実行し、
Qtの型を小さなテスト用代替型で扱っている。
自動翻訳の検査も現行ソースの処理を抽出し、メッセージ・ロケール・UIの
可視状態をテスト用の型で代替する。実際の翻訳サービスへの通信は未検証。

### Apple Silicon Mac の Debug ビルド

このフォークには [依存準備](../tools/macos_debug/prepare.py) と
[本体ビルド](../tools/macos_debug/build.sh) のスクリプトを同梱する。
リポジトリの `AGENTS.md` は全体ビルドを避けるよう指示しているため、
エージェントが実行するときはユーザーの明示的な上書き指示が必要。
上流の手順は [building-mac.md](building-mac.md)。

Xcode と Homebrew のツールを用意して、リポジトリのルートで実行する。

```sh
brew install git automake libtool cmake wget pkg-config gnu-tar ninja nasm meson
PATH="$(brew --prefix libtool)/bin:$(brew --prefix gnu-tar)/libexec/gnubin:$PATH" \
  python3 tools/macos_debug/prepare.py
bash tools/macos_debug/build.sh
```

依存ライブラリは上流と同じ隣接フォルダ `../Libraries`、`../ThirdParty`
に保存する。Qt 6.11.1 と本体は arm64 の Debug 構成だけを作る。
そのほかのライブラリは上流の共通構成を使い、Intel/arm64 両方を含む。
共通ライブラリの一部は上流指定の最適化構成を使う。
アプリの Release 構成は作らない。

準備スクリプトは上流のキャッシュを使い、完成済みの段階を再利用する。
libiconv 1.18 は kernel.org の GNU ミラーから取得し、
[Homebrew の同バージョンの履歴](https://github.com/Homebrew/homebrew-core/blob/a2b3d3befee2684c5d6390cc5733752c7d5b735e/Formula/lib/libiconv.rb)
にある SHA-256 と照合する。
自動更新とクラッシュレポートは無効にし、不要な crashpad/breakpad は準備しない。

Xcode 27 に合わせ、本体の deployment target は 12.0 にする。
range-v3 の古い標準コンテナ宣言を避けるため、C++ と Objective-C++ に
`META_NO_STD_FORWARD_DECLARATIONS=1` を指定する。
ビルドスクリプトの API ID/hash は上流が公開している開発用の値を使用する。

完成した `out/Debug/AyuGram.app` にローカルの ad-hoc 署名を付け、検証する。
同じ階層の `out/Debug/TelegramForcePortable` を保存先にするため、
初回は新規プロファイルで起動する。アカウントデータはこのフォルダ内の
`tdata` に保存される。`out/` の削除や clean の前には、保存先を `out/` の
外へバックアップする。

実行中のアプリを残して修正版を作る場合は、別の出力先を指定する。

```sh
bash tools/macos_debug/build.sh out/parallel-export-fix/Debug
```

出力先はCMakeの生成時に設定し、実行ファイル、リソース、Swiftランタイムの
コピー、署名の対象を同じ別フォルダに揃える。ビルドだけでは実行中のアプリは
切り替わらない。新しい出力先に作られる `TelegramForcePortable` は空なので、
既存のアカウントを使うには先のアプリを終了してから同じ `-workdir` を指定する。

### このMacでの起動確認

2026-10-06、Xcode 27 で arm64 の Debug ビルドが完了し、
ad-hoc 署名の検証も通過した。既存のインストール済みアプリとは別の、
未ログインの新規プロファイルで起動した。

言語一覧から日本語を選ぶと、設定、ログイン案内、匿名モード、終了メニューが
日本語になった。英語へ戻して再び日本語を選ぶ操作も確認した。
クラウド応答の `ja-raw` を取り込み、同梱していない「接続方式」と
「丸型アイコン」が日本語になった。通常の終了操作後に起動し直しても
日本語が保持され、ログはキャッシュの 11,428 エントリを読み込んだ。
この件数は保存パックのエントリ数で、現行UIの日本語訳済みキー数ではない。

起動時の日本語パック読み込みエラーや、別名応答を無視する警告は出ていない。
ログイン済みのチャット画面、複数チャットの実データ取得、翻訳サービスとの
通信は、この新規プロファイルではまだ確認していない。

その後ユーザーがログインしたこのプロファイルでは、2026-10-07に
一件の出力が完了し、画面に2,038ファイル・273.3 MBと表示された。
これはTakeout修正前のアプリでの結果であり、複数同時出力の確認ではない。

Takeout修正版は `out/parallel-export-fix/Debug/AyuGram.app` に作成した。
2026-10-07、arm64のDebugビルドとad-hoc署名の検証が通過した。
実行中だった旧アプリの全17ファイル・リンクはビルド前後でハッシュ等が一致し、
修正版には実行ファイルと両リソースファイルが揃っている。
実アカウントでの同時書き出し確認は、旧アプリから切り替えた後に行う。

作業領域の実測は依存ライブラリ約17 GiB、`out/` 約5.9 GiB。
`AyuGram.app` は約1.2 GiBで、この容量は `out/` の内数である。
